# Спецификация: реврайтинг текста + двухуровневая коррекция

**Ветка:** `feat/llm-postproc-gec` · **Дата:** 2026-08-22
**Основание:** benchmark/REPORT.md (LLM Benchmark Report, 2026-08-21) + решение пользователя от 2026-08-22.

## 1. Решения, зафиксированные в этой ветке

1. **Быстрая модель коррекции = VoiceScribe V15 R-3** (Qwen3.5-0.8B Q6_K +
   LoRA-адаптер dictation-corrector, `--lora-scale 4.0`). Уже вендорена в
   ветке; настоящей спекой фиксируется как уровень «Быстрая» (по умолчанию).
   Обоснование (REPORT.md): p50 189 мс, Identity 1.000, вес 0.7 ГБ.
2. **Качественная модель коррекции = YandexGPT-5-Lite-8B-instruct Q4_K_M**
   (уровень «Качественная», скачивается по требованию). Обоснование:
   EM 0.892, Levenshtein 0.985, Identity 1.000, p50 433 мс.
3. **Модель реврайта = YandexGPT-5-Lite-8B-instruct Q4_K_M** (тот же файл,
   что и качественная коррекция — одна загрузка на оба применения).
   Обоснование: FactRec 0.527 (лучший), LenRatio 0.966, p50 2668 мс.
4. **Реврайт и коррекция — независимые переключатели** (заменяет правило
   атома a81da166 §16 «rewrite ON → GEC OFF»): пользователь может включить
   оба одновременно. Порядок пайплайна при обоих включённых:
   ASR → детерминированный слой → **коррекция** → **реврайт**
   (сначала исправить ошибки распознавания, затем менять структуру/стиль).
5. **Независимые кастомные endpoints**: у коррекции и у реврайта свои
   отдельные поля «движок / base URL / API-ключ / имя модели» — два
   произвольных OpenAI-совместимых endpoint'а одновременно.

## 2. Модели и пины

### 2.1 Быстрая коррекция (без изменений, фиксация)

Существующий пин `GEC_MODEL_*` (bartowski/Qwen_Qwen3.5-0.8B Q6_K @
`f36b1ea4`, SHA256 `9762…7f95`, 691 461 216 Б) + LoRA `GEC_LORA_*`
(VoiceScribe V15 R-3, rsLoRA, scale 4.0). Промпт: существующий
`LLMCorrectionPrompt` (few-shot, тюнен под адаптер). Guardrail:
`LLMCorrectionGuardrail` (сохранение первого слова).

### 2.2 YandexGPT-5-Lite-8B (качественная коррекция + реврайт)

- Репозиторий: `yandex/YandexGPT-5-Lite-8B-instruct-GGUF` (официальный).
- Ревизия: `9fe287d2f512503046bb008aed350f2b4bbb903d` (пин, никогда main).
- Файл: `YandexGPT-5-Lite-8B-instruct-Q4_K_M.gguf`
- Размер: `4_920_741_184` Б; SHA256
  `d9ff5b826f20fbcc2f898f9f2349ac21241579f8fbb79cd32148a333623ba228`
  (вычислен по фактическим байтам локальной копии из benchmark/models,
  совпадает с LFS-метаданными HF — та же самая проверенная на бенчмарке
  модель).
- Кэш: `…/Models/LLM/YandexGPT-5-Lite-8B-instruct-Q4_K_M.gguf` (брат
  GEC-файлов). Проверка места на диске: ~5.42 ГБ (вес + headroom).
- Хост: тот же SuperDictateLLMHost, БЕЗ LoRA, ctx-size 8192 (реврайт
  длинных фрагментов: промпт + до ~3072 токенов выхода).
- Промпт коррекции для этого уровня: benchmark-валидированный
  zero-shot `correction.txt` (EM 0.892), без few-shot-пар VoiceScribe.
  Guardrail применяется тот же (политика «не терять текст»).

## 3. Режимы реврайта (3)

Системный промпт: база из benchmark-валидированного `rewrite.txt`
(сохранение фактов/чисел/дат/названий/отрицаний, запрет новых фактов,
«верни только итоговый текст») + явный блок инструкций режима. Пользовательский
ход: текст + суффикс `Режим: <MODE>` (как в бенчмарке). Temperature 0,
thinking off, maxTokens `min(3072, max(256, 3×utf8.count))`, timeout 90 с.

| Режим | raw value | Что делает |
|---|---|---|
| Причесать текст | `polish` (умолчание) | Убрать повторы слов и мыслей, несогласование падежей, бессмысленные отрезки («в принципе», «как бы», «скажем так», «ну как бы дальше», «и так далее»). Стиль и порядок мыслей близки к оригиналу. Смысл не меняется. |
| Структурировать в задачу | `structured_task` | Вольный текст → чёткая структурированная задача: суть/цель, главное, второстепенное, шаги. Вычленить важное, отсечь повторы и логические ошибки, ничего не выдумывать. |
| Официальный стиль | `official` | Casual-речь → сухой формальный логичный текст. Без разговорных оборотов; все факты, числа, даты, сроки, отрицания сохранены дословно. |

Guardrail реврайта: только «не вернуть пустоту» → откат ко входу
(leading-word guardrail НЕ применяется — реврайту разрешена
реструктуризация).

## 4. Настройки (UserDefaults, suite com.local.superdictate)

| Ключ | Тип | Умолчание | Назначение |
|---|---|---|---|
| `correction_model_tier_v1` | String | `fast` | Уровень коррекции: `fast` \| `quality` |
| `rewrite_enabled_v1` | Bool | `false` | Реврайт вкл/выкл (независимо от коррекции) |
| `rewrite_style_v1` | String | `polish` | Режим реврайта (§3) |
| `rewrite_engine_backend_v1` | String | `bundled_local` | `bundled_local` \| `custom_endpoint` |
| `rewrite_custom_base_url_v1` | String | `""` | Base URL реврайта (свой endpoint) |
| `rewrite_custom_api_key_v1` | String | `""` | API-ключ реврайта |
| `rewrite_custom_model_name_v1` | String | `""` | Имя модели реврайта |

Существующие ключи `text_postprocessing_mode_v1`, `llm_engine_backend_v1`,
`llm_custom_*` остаются ТОЛЬКО про коррекцию (без миграции: новые ключи
читаются с безопасными умолчаниями). Хоткей коррекции переключает только
коррекцию.

## 5. Пайплайн и процессы

`LLMPostprocessingCoordinator.finalizedText(_:settings:)` — сигнатура не
меняется (3 call-сайта ParakeyApp не трогаем):

```
вход (после processedDictationText)
 → коррекция,  если textPostprocessingMode == .correction
    (tier: fast → хост#1 qwen+lora / quality → хост#Y yandex;
     backend: bundledLocal | customEndpoint — как сегодня)
 → реврайт,    если rewriteEnabled
    (backend: bundledLocal → хост#Y yandex (ШТАТНО ДЕЛИТ процесс
     с качественной коррекцией — identity = путь к модели+LoRA);
     customEndpoint → свой URL)
 → возврат текста; ЛЮБОЙ сбой любой стадии = вернуть текст входа
```

- Хосты: словарь `LLMHostProcess` по identity `modelPath|loraPath`
  (быстрая коррекция — свой хост; YandexGPT — один общий на
  качественную коррекцию и реврайт; запросы сериализованы мьютексом
  хоста, стадии последовательны).
- Выгрузка: `scheduleDelayedUnload()` через 10 мин останавливает только
  хосты, не нужные ни одной включённой функции по текущим настройкам
  (коррекция выкл., реврайт вкл. на общем YandexGPT-хосте → хост жив).
  `cancelScheduledUnload()` / `stop()` — как сегодня.
- VRAM-риск (0.7 + 4.9 ГБ на 8 ГБ GPU при обоих уровнях): принимается;
  отказ хоста = pass-through текста (существующая политика).

## 6. UI (вкладка «Коррекция» → секции)

**Секция «Коррекция»**: существующий тумблер; НОВЫЙ попап уровня
(«Быстрая — VoiceScribe, ~0,7 ГБ, ~0,2 с» / «Качественная — YandexGPT 5
Light, ~4,9 ГБ»); существующий попап движка; для bundled — строка статуса
модели выбранного уровня (скачать/готова; для quality — YandexGPT);
для custom — 3 существующих поля.

**Секция «Реврайтинг текста»**: тумблер; попап режима (3 значения, §3);
попап движка («Встроенная — YandexGPT 5 Light локально» / «Свой сервер»);
для bundled — общий статус YandexGPT (тот же файл); для custom — 3 своих
поля (теги 9004–9006).

## 7. Тесты

- Герметичные (в `all`): умолчания/нормализация новых настроек;
  независимость тумблеров; выбор промпта реврайта по режиму; выбор
  промпта коррекции по уровню; идентичность identity для
  quality+rewrite-bundled; расширенный delayed-unload (общий хост жив,
  если реврайт включён).
- Интеграционные (НЕ в `all`): `llm-gec` (быстрая модель, без изменений);
  НОВЫЙ `llm-rewrite` — env `SUPERDICTATE_YANDEXGPT_MODEL` (стадируется в
  кэш как llm-gec), проверяет все 3 режима на нетривиальных входах.

## 8. Сборки

Тестовое приложение: `TEST_APP_LABEL=llm-rewrite scripts/build-test-app.sh`
→ `dist/SuperDictate-llm-rewrite.app` (com.local.superdictate.llm-rewrite,
отдельная TCC-идентичность, /Applications не трогается). Уровень коррекции
по умолчанию — быстрый (VoiceScribe), что и требовалось зафиксировать.
