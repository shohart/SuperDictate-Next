# SuperDictate для Windows

Локальная диктовка по горячей клавише: нажали, сказали, текст появился в
активном поле ввода. Ничего не уходит в сеть.

Это Windows-версия [SuperDictate Next](../README.md) — та же модель
распознавания, те же настройки, те же промпты постобработки. Код свой:
Python + PySide6 вместо Swift + AppKit, но поведение и имена настроек
общие, чтобы одинаковое означало одинаковое на обеих платформах.

Происхождение и что взято за основу — в [PROVENANCE.md](PROVENANCE.md),
цепочка авторства — в [NOTICE.md](NOTICE.md).

> **Состояние: в разработке.** Часть возможностей macOS-версии ещё не
> перенесена — список ниже, в разделе «Чего пока нет». Готовых сборок нет.

## Что уже работает

**Распознавание речи** — тот же движок и те же модели, что в macOS-версии
с 0.7.0: нативный хост `SuperDictateOnnxHost` (C++-ядро из
[`native/asr-runtime`](../native/asr-runtime), ONNX Runtime 1.23.2) в
отдельном процессе, только на процессоре. Модели качаются по общему
закреплённому каталогу с проверкой SHA-256:

| модель | языки | размер |
|---|---|---|
| Parakeet Ultra 0.6B, int8 (по умолчанию) | 25, включая русский | ~600 МБ |
| GigaAM v3 e2e RNN-T, int8 | только русский: пунктуация, регистр, ё, цифры | ~220 МБ |

Видеокарта отдана языковой модели: Parakeet на ней не выигрывает, а
постобработка ускоряется в разы.

**Нейропроцессор Intel (NPU).** На ноутбуках с Intel Core Ultra
(«Intel AI Boost») в «Настройки → Дополнительно → Где распознавать»
появляется пункт «Нейропроцессор». Там работают те же два профиля, но в
сборках OpenVINO, во втором хосте `SuperDictateOvHost.exe`
(`superdictate/openvino_host.py`, тот же IPC v1). Модели ставятся в
`Models\openvino\` по своему закреплённому каталогу
(`assets/openvino-models.json`):

| профиль | модель для NPU | размер |
|---|---|---|
| Parakeet | [Parakeet TDT 0.6B v3, OpenVINO](https://huggingface.co/VoiceScribe/voicescribe-parakeet) | ~1,2 ГБ |
| GigaAM | [GigaAM v3, энкодер откалиброван под NPU](https://huggingface.co/VoiceScribe/voicescribe-gigaam-npu) + декодер из [voicescribe-gigaam](https://huggingface.co/VoiceScribe/voicescribe-gigaam) | ~220 МБ |

При первом запуске модель компилируется под NPU: Parakeet около 20 с,
GigaAM от 4 до 10 минут. Компиляция идёт в фоне. Если она не уложилась
в 15 с, энкодер стартует на процессоре (те же веса, тот же текст) и
переходит на NPU между диктовками, когда компиляция закончится
(`EncoderSlot` в `openvino_asr.py`). Результат кэшируется в
`Models\openvino\compiled`, и дальше загрузка занимает 1–3 с.
Компилируется встроенным в OpenVINO
NPU-компилятором, а не драйверным: драйверный (32.0.100.3159) не
принимает гибридный энкодер GigaAM. Если NPU не поднялся, распознавание
остаётся на процессоре. Проверка без интерфейса:
`python main.py --benchmark-transcribe gigaam_v3_onnx --npu файл.wav`.

**Постобработка локальной языковой моделью** — то же, что на маке, теми
же весами и теми же промптами:

* **Коррекция** — исправляет ошибки распознавания, регистр и пунктуацию,
  а главное — возвращает английским терминам латинское написание: «задеплоил
  в кубернетис через докер компоуз» → «задеплоил в Kubernetes через
  Docker Compose». По умолчанию Qwen3.5-0.8B с дообученным адаптером; на
  выбор те же модели, что на macOS (4B-модели, YandexGPT 8B).
  Результат проходит через защитный барьер: если модель потеряла первое
  слово или выдумала термин — берётся исходный текст, не исправленный.
* **Рерайт** — три режима: «причесать» (убрать повторы и мусор, сохранив
  стиль), «задача» (развернуть в структурированное ТЗ) и «официальный»
  (деловой регистр). Модели те же, что в рерайте на macOS (YandexGPT 8B,
  Qwen3.5-9B, Gemma 4 E4B, 3–4B-модели).

Обе стадии работают локально, на встроенном хосте llama.cpp (тот же, что
на macOS), на процессоре или видеокарте (Vulkan: NVIDIA, AMD, Intel Arc),
или через OpenAI-совместимый API. Видеокарте приложение не верит на слово:
при первом запуске модели на GPU она должна дословно повторить короткую
фразу, и если вместо неё приходит мусор или NaN, эта модель до конца сессии
считается на процессоре (с уведомлением в капсуле).

Обе стадии независимы, могут работать вместе, и **ни при каком сбое не
теряют текст**: не скачалась модель, не поднялся хост, истёк таймаут —
возвращается то, что было на входе.

**Словарь исправлений** — на SQLite, с автоматическим запоминанием, как на
macOS: 45 секунд после вставки приложение следит за полем через UI
Automation (`superdictate/edit_watch.py`). Поправили там же одно–три слова
(«инглиш» → «English») и 4 секунды ничего не меняли — правило запомнено.
Пока идут эти 4 секунды, над полем висит пилюля «инглиш → English», как на
macOS: Enter запоминает сразу, Esc или щелчок отменяют (пара зачёркивается).
Удаление, правка только регистра, правка вне вставленного текста и поля
паролей не запоминаются.
Импорт-экспорт **в том же версионированном формате**, что файл
синхронизации macOS-версии, так что словарь переезжает между платформами
без конвертации.

**Длинная диктовка** — режется по паузам, а не по часам: короткая
диктовка с обычным вдохом между фразами проходит одним куском, и только
по-настоящему длинная начинает резаться. Соседние куски перекрываются,
точку передачи выбирает Silero VAD по самой тихой точке, а слово,
услышанное дважды на шве, выбрасывается (`superdictate/transcription.py`,
порт `transcribeSegmented`).

**Капсула** — полоски уровня или таймер диктовки (появляется после
десяти секунд, чтобы короткие фразы не превращались в секундомер),
настраиваемые цвета и размер.

**Остальное** — автостоп по тишине, числа цифрами, удаление
слов-паразитов, история диктовок, автозапуск, приглушение звука на
время записи.

## Чего пока нет

Перенос идёт, и это честный список того, чего в Windows-версии ещё нет:

| | |
|---|---|
| Цвет HUD «Contrast» | смысла не имеет, пока капсула всегда тёмная — см. ниже |

**Про «Contrast». На macOS этот цвет подстраивается под фон капсулы:
тёмный на светлом, белый на тёмном. Здесь капсула всегда тёмная
(`CAPSULE_FILL` — константа), так что «Contrast» всегда разрешался бы в
белый, который уже есть в списке. Переносить его имеет смысл только вместе
со светлой темой капсулы — это отдельная работа, а не перенос настройки.

**Про слова-паразиты.** Ранняя редакция этого файла утверждала, что здесь
плоский список вместо кураторских пресетов. Это была ошибка: пресетов
здесь **38** против 27 на macOS, чеклист в четыре колонки и поле для своих
слов уже на месте. Различается только хранение — macOS держит стабильные
ключи (`ru_tipa`), здесь список включённых слов; стоит унифицировать ради
переноса настроек, но функционально всё есть.

## Горячие клавиши

| Действие | Клавиши |
|---|---|
| Диктовка | правый **Ctrl** |
| Завершить по-другому (вставить + Enter) | **Alt** + правый **Ctrl**, во время записи |
| Отмена записи | **Esc** |
| История | **Shift** + правый **Ctrl** |
| Коррекция вкл/выкл | **Ctrl + Alt + C** |
| Рерайт вкл/выкл | **Ctrl + Alt + R** |
| Следующий режим рерайта | **Ctrl + Alt + S** |

Второе сочетание работает, как на macOS. Нажатое во время записи, оно
завершает диктовку противоположным действием: если основное сочетание
только вставляет текст, второе вставит его и нажмёт Enter, и наоборот.
Удобно, чтобы указание агенту или сообщение в чат уходило сразу. Его
можно выключить.

Три последних сочетания отличаются от macOS-версии, где они на F13–F15:
таких клавиш почти нет на PC-клавиатурах. Alt+Shift и Ctrl+Shift не
заняты намеренно — это переключение раскладки. Всё перенастраивается
в «Настройки → Сочетания».

## Запуск из исходников

Готовых сборок пока нет. Нужны Python 3.11 (зависимости закреплены под
него), CMake и Visual Studio 2022 / Build Tools с C++.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
.\tools\build-onnx-host.ps1        # хост распознавания -> onnx-asr\
python main.py
```

Silero VAD собирается в `engines\` отдельным скриптом (его вызывает и
`build.ps1`); без `engines\silero-vad.dll` швы длинной диктовки
выбираются по энергии сигнала:

```powershell
.\tools\build-engines.ps1        # silero-vad.dll -> engines\
```

Локальные коррекция и рерайт идут через тот же хост, что на macOS
(`superdictate-llm-host.exe`, вендоренный llama.cpp с CPU и Vulkan). Его
собирает `build.ps1` через `tools\build-engines.ps1 -ExperimentalLlmHost
-Vulkan`, для сборки нужен Vulkan SDK. Хост держит снимок общего начала
промпта коррекции (системный промпт и примеры, ~276 из ~295 токенов) и
считает только саму фразу. Модель грузится и прогревается в фоне, когда
приложение готово. Веса VoiceScribe лежат в
`%LOCALAPPDATA%\SuperDictate\Models\llm\` и скачиваются из настроек. Там же
выбирается процессор или видеокарта.

Замеры на Core Ultra 5 225H (Arc 130T, драйвер 32.0.101.6554), корпус из 65
фраз `benchmark/corpus/correction.jsonl`:

| бэкенд | медиана / p90 на фразу | качество |
|---|---|---|
| **CPU, наш хост, 8 потоков** | **0,25 / 0,34 с** | 63/65 ответов как у эталона |
| **Vulkan, наш хост** | **0,44 / 0,52 с** | EM 0,646 |
| CPU, `llama-server` (до 0.8.3.1) | 0,32 / 0,43 с | EM 0,646, эталон |
| Vulkan, `llama-server` | 0,50 / 0,58 с | как CPU |
| Vulkan по умолчанию | 0,40 с | **пустые и мусорные ответы** |
| SYCL | не запускается на этом драйвере | — |
| llama.cpp + OpenVINO | Qwen3.5 не поддерживается (ошибка графа) | — |

Две настройки хоста обязательны, и `llm/host.py` (`host_command`)
выставляет их сам:

* **Шейдеры cooperative matrix выключены.** На этом драйвере Intel они
  ломают пакетную обработку промпта; без них Vulkan и корректен, и
  быстрее.
* **Потоков — физические ядра минус два, не больше 8.** На всех 14 ядрах
  225H (вместе с E- и LP-ядрами) пул потоков ждёт самый медленный поток
  на каждом барьере. Стоит другим программам занять процессор, и
  коррекция растягивается на минуты.

`tools\fetch-llama.ps1` (официальный `llama-server`) остался как
запасной хост: приложение возьмёт его, если в сборке нет своего.

Коррекцию и рерайт можно направить и во внешний OpenAI-совместимый API
(LM Studio, Ollama, облако): адрес, ключ и модель задаются в настройках.

Релизы Windows помечаются тегами `win-vX.Y.Z` и никогда не отмечаются
как «Latest» (так их не увидят mac-клиенты). Как собрать и опубликовать
релиз — в [`docs/RELEASING.md`](../docs/RELEASING.md).

Самопроверка, без микрофона и модели:

```powershell
python main.py --self-test
```

Распознавание настоящим хостом, без интерфейса (WAV 16 кГц моно):

```powershell
python main.py --benchmark-transcribe parakeet_ultra_onnx запись.wav
python main.py --benchmark-transcribe gigaam_v3_onnx запись.wav
```

## Данные

Всё лежит в `%LOCALAPPDATA%\SuperDictate\`:

| | |
|---|---|
| `Settings.json` | настройки |
| `History.json` | история диктовок |
| `corrections.sqlite` | словарь исправлений |
| `Models\` | веса моделей (`Models\onnx\<model_id>\` — распознавание) |
| `Logs\` | логи |

Установка поверх старой сборки под именем `Dictation` переносит эту папку
автоматически — ничего скачивать заново не нужно.
